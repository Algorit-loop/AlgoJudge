B. Dữ liệu bài toán judge phải có sẵn (trên đĩa)

/problems/aplusb/
├── init.yml          ← cấu hình: danh sách test, điểm, checker...
├── aplusb.1.in       ← input test 1  (được đưa vào stdin của chương trình)
├── aplusb.1.out      ← output đúng test 1 (dùng để so sánh)
├── aplusb.2.in / .out
└── aplusb.3.in / .out

Các khóa hay dùng trong init.yml: test_cases (mỗi phần tử in, out, points, hoặc batched để gom test thành nhóm), archive (file zip chứa dữ liệu), checker (cách so output), generator, output_prefix_length, binary_data, hints, symlinks, pretest_test_cases. Các chế độ chấm khác (grader): standard, interactive, signature, output-only, custom/bridged checker.

C. Judge xử lý một test (vào gì, ra gì)

BướcVàoRa
1. Biên dịchsource + executorFile thực thi. Nếu lỗi → CE kèm log (dừng, không chạy test). Cảnh báo → compile message.
2. Chạy trong sandboxNội dung .in → stdin; giới hạn TL / MLstdout của chương trình; mã thoát / tín hiệu; CPU time, wall time, bộ nhớ đỉnh, context switch
3. Checkerstdout thí sinh + nội dung .outĐúng/sai (+ điểm từng phần nếu checker hỗ trợ) và feedback. Checker mặc định so từng token, bỏ qua khoảng trắng thừa.
4. Tổng hợpKết quả từng test + điểm trong init.ymlVerdict từng test, điểm từng test, tổng điểm.

Chương trình thí sinh chỉ có stdin → stdout: không nhận tham số dòng lệnh, không được mở/ghi file tùy ý, không được mạng, không fork. stderr bị bỏ qua (chỉ dùng để suy ra feedback khi crash).

D. Đầu ra của judge

Mỗi test case (test_case_status_packet):

TrườngÝ nghĩa
codesDanh sách verdict, phần tử đầu là chính (xem bảng bên dưới). Có thể kèm cờ phụ, ví dụ ["IR","WA"].
time / wall_timeCPU time / thời gian thực (giây).
memory_kbBộ nhớ đỉnh (KB).
points / total_pointsĐiểm đạt được / điểm tối đa của test.
feedbackLý do ngắn: segmentation fault, Exit code 3, std::bad_alloc…
extended_feedbackThông tin thêm từ checker (ví dụ 1 token(s)).
outputPhần đầu stdout của chương trình (cắt theo output_prefix_length, mặc định 128 byte).
context_switches, runtime_version[tổng, cưỡng bức]; phiên bản runtime đã dùng.

Toàn bài nộp: begin_grading → (compile_message | compile_error) → các test_case_status (có thể trong batch_begin/batch_end) → grading_end; lỗi nội bộ thì internal_error; hủy thì submission_aborted. Trang web gom hết thành một JSON: verdict, points, total_points, grading_seconds, compile_error, compile_message, internal_error, cases[], log.

E. Bảng verdict

MãKhi nào
ACOutput khớp đáp án, không vi phạm giới hạn.
WAChương trình chạy xong nhưng output sai.
TLEVượt time limit.
MLEVượt memory limit.
OLEIn quá nhiều output (giới hạn mặc định 24 MB).
RTEBị signal (segfault, abort…) hoặc vi phạm sandbox.
IRInvalid Return: thoát với exit code ≠ 0.
CEBiên dịch thất bại (không có test nào chạy).
SCBỏ qua do short-circuit (batch đã có test sai).
IELỗi nội bộ của judge.

F. API của trang web này (bọc ngoài judge)

POST /api/submit nhận:

{"problem":"aplusb","language":"CPP17","source":"...","time_limit":2,"memory_limit":65536}

và trả JSON kết quả như mục D. GET /api/info trả thông tin judge, danh sách runtime và dữ liệu bài. Ở phần “Kết quả chấm” bên dưới có mục JSON thô để xem đúng request / response của lần chấm gần nhất.
